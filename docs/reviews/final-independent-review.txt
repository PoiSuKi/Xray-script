2. **Medium — Debian 11 bootstrap is broken by `bind9-dnsutils`, contradicting the README.** [install.sh:322](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/install.sh:322) and [install.sh:372](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/install.sh:372) install `bind9-dnsutils`, but that package name only exists on Debian 12+; Debian 11 (bullseye) provides `dnsutils`. The README claims Debian 11 support at [README.md:157](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/README.md:157). On Debian 11, `apt install bind9-dnsutils` fails and the install cannot proceed. Pre-existing (commit `429ec51`), not introduced by this diff.

3. **Low / needs verification — Xray service user ownership is not actually enforced.** `handler_xray_runtime_compat` creates the `xray` user/group and chowns the config to `root:xray` `0640` and `/var/log/xray` to `xray:xray` `0700` ([handler.sh:1855-1863](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/core/handler.sh:1855)), but the script passes `--no-update-service` and never writes `User=` in the `xray.service` unit ([handler.sh:1949](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/core/handler.sh:1949)). The service therefore runs as whatever the pinned official installer hard-codes. If that unit runs as `root`, it works but the “dedicated xray user” hardening is cosmetic; if it runs as `nobody`, startup fails on log/config permissions. I could not fetch the pinned installer offline to confirm which is true.

4. **Low — `latest` version selection does not exclude prereleases.** [handler.sh:1698-1702](C:/Users/YuuDaChi/Documents/Codex/2026-11-05/https-github-com-zxcvos-xray-script/work/fork/core/handler.sh:1698) filters only `.draft != true`, so menu option “latest” can select a prerelease if Xray-core publishes one ahead of a stable tag.
